# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-11-18 | Use OpenRouter's OpenAI-compatible chat API through `httpx` for the optional AI brief. | Approved provider; no new SDK dependency is required. |
| 2026-11-18 | Use `stats/punch_card` for busiest weekday/hour metrics and drop the `/commits` endpoint. | Covers the needed time distribution in one stats call with the same 202 retry policy. |
| 2026-11-18 | Store every analysis result in memory under a random `analysis_id` for `CACHE_TTL_SECONDS`; `/brief` and `/api/brief` accept only `analysis_id`. | Lets brief generation reuse fetched data without asking for tokens again while keeping private results unlisted and unkeyed by repo name. |
| 2026-11-18 | Fetch README during analysis only when a brief is possible. | Avoids an extra GitHub call when no LLM key/model is configured or private ZDR is disabled. |
| 2026-11-18 | Cache by repo name only for complete public analyses made without a per-request user token; `GITHUB_TOKEN` analyses may cache. | Prevents private, token-specific, or partial results from being reused as public recent analyses. |
| 2026-11-18 | Fetch contributor page 1 concurrently; with any token, read `rel="last"` and fetch remaining pages concurrently up to 5 total pages; without a token, show page 1 plus a token notice. | Balances GitHub rate limits with useful contributor coverage and bus-factor accuracy. |
| 2026-11-18 | Apply the shared rate-limit gate only to requests without a user token; user-token requests skip the gate and do not update shared state. | User tokens have separate GitHub rate-limit budgets and must not affect anonymous/shared throttling. |
| 2026-11-18 | Cap `AnalysisStore` at 500 entries with oldest-first eviction in addition to TTL expiry. | Bounds memory use while preserving recent analysis IDs for briefs. |
| 2026-11-18 | Vendor htmx `2.0.11` and Chart.js `4.6.1` from official npm package tarballs; record version, source URL, and SHA-256 when vendored. | Keeps the app self-contained without CDN dependencies or floating frontend versions. |
| 2026-11-19 | Defer `/brief` and `/api/brief` to the LLM step; no stub routes. | Brief endpoints cannot work before `llm.py` exists, so they ship together in step 5. |
| 2026-11-19 | Key the repo-name cache by the lowercased GitHub `full_name`; lookups lowercase the input. | GitHub names are case-insensitive, so `Octo/Repo` and `octo/repo` must share one cache entry. |
| 2026-11-19 | Results with pending stats sections are not repo-name cached. | Only complete analyses may be reused as recent/public results. |
| 2026-11-19 | `RepoRef.parse` trims input, requires a github.com host when a host is present, and validates owner/repo character sets; deeper paths are ignored. | FR1 normalization must reject non-GitHub hosts and invalid names while accepting common URL forms. |
| 2026-11-19 | Vendored `htmx.min.js` from `htmx.org@2.0.11` (npm tarball SHA-256 `165a2655073e9e6e55e307a7c74e8ebcdb76afb7701f9c16cfd106a13add408e`, file SHA-256 `d6fdc75f204e6bdefa99b69bf1e6d4ac69b8a364f77929f45c13476b4000f717`, https://registry.npmjs.org/htmx.org/-/htmx.org-2.0.11.tgz) and `chart.umd.min.js` from `chart.js@4.6.1` (npm tarball SHA-256 `9345dacdf4bb4c5d40321f4b9aafab6fe676d37a534fc0bc2d17c4c4e29c4f00`, file SHA-256 `87364cc2b2a76a6684929e7d6b80b18a897794db38400caff1fcf1791c6925d2`, https://registry.npmjs.org/chart.js/-/chart.js-4.6.1.tgz). | Self-contained frontend with pinned versions per the vendoring decision. |
| 2026-11-19 | htmx 4xx/5xx error swaps enabled via `htmx-config` meta `responseHandling` (`[45]..` swap+error); codes are regexes matched against the status. | htmx 2 ignores error responses by default; the meta config is the documented mechanism. |
| 2026-11-19 | Total commit count uses `GET /commits?per_page=1` and the `rel="last"` page number; no Link header means the returned count (0 or 1), 409 means 0, other failures mark the section unavailable. | One cheap call yields an exact all-time count on the default branch. |
| 2026-11-19 | `AnalysisStore` entries hold the report plus optional README (first 8,000 chars), brief, and private flag; briefs are generated once per `analysis_id` and cached in memory. | `/brief` only receives an `analysis_id`, so the README and generated brief must live with the stored analysis; caching avoids repeat paid calls. |
| 2026-11-19 | Brief unavailability (no key/model, or private without ZDR) is a normal 200 state with `brief: null` and a reason, for both API and HTML; only LLM failures are 502 and are never stored. | FR9 treats missing configuration as a display state, not an error; failed generations must be retryable. |
| 2026-11-19 | Brief schema asks for ~3 points per section in the prompt; code trims to 3 and drops any point with empty or unknown `fields` (fields must come from the metrics context keys). `max_tokens` is 4000 and any `finish_reason` other than `stop` fails. | LLM output is untrusted; grounding keeps every claim tied to computed numbers. |
| 2026-11-19 | The LLM context is metadata, metrics, and top-10 contributors as login+commits only — no URLs or avatars; `json_schema` is generated via `Brief.model_json_schema()`; `provider.require_parameters=true` always, `provider.zdr=true` only for private repos; timeout 60s. | Prompt minimization and schema adherence per privacy rules. |
| 2026-11-19 | One `app.llm` log line per OpenRouter call with model, result, elapsed time, token counts, cost, dropped points, and generation id; `LOG_LEVEL` sets only the `app` logger while the root stays at WARNING. | Telemetry for brief calls without leaking prompts, READMEs, brief text, keys, or repo names into logs (httpx logs full URLs at INFO). |
